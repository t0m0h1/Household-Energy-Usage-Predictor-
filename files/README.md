# Household Energy Usage Predictor

A beginner-friendly machine learning dashboard that predicts household electricity use (kWh) with a
scikit-learn **Random Forest Regressor**. It uses only free, open-source Python libraries and runs
entirely offline once installed - no API keys, accounts or downloads of data.

> The built-in dataset is **synthetic demonstration data** generated by Python. It is not a real
> household. Results on it show that the pipeline works, not how your own home behaves.

## What the app does

| Page | Purpose |
|---|---|
| Overview | Summary cards, usage over time, average usage by hour, date-range filter |
| Predict Usage | Choose a date, time, temperature and recent usage, then get a prediction |
| Usage Trends | Time series, hour/weekday patterns, usage vs temperature, actual vs predicted |
| Model Performance | MAE, RMSE, R² on held-out data, baseline comparison, feature importance |
| Dataset and Settings | Upload CSV, preview and cleaning report, train/retrain, reset, download |

## How supervised learning works here

In *supervised learning* the model learns from examples where the answer is known. Each example is
one hour: the **inputs (features)** describe the situation and the **target** is the real usage in kWh.
The model finds patterns linking inputs to targets, and is then asked to predict hours it has not seen.

**Features:** temperature (if available), hour, weekday, month, season, weekend flag, usage 1, 2 and 24
hours earlier, and the average of the previous 3 and 24 hours.

**Random Forest:** many decision trees (here 100), each trained on a random sample of the data. Each
tree predicts and the forest averages the answers. Settings: `n_estimators=100`,
`min_samples_leaf=2`, `random_state=42` (so results are reproducible).

## How the model is trained

1. Data is cleaned and placed on a complete hourly grid.
2. Features are built. Every lag and rolling feature uses `shift(1)` first, so it only sees readings
   **before** the hour being predicted (no *data leakage*).
3. Rows are split **chronologically**: the first 80% of time for training, the last 20% for testing.
   Shuffling would let the model peek at the future.
4. The forest is fitted on the training part only, then scored on the test part.
5. The model is saved to `model.joblib`. It is reused if the data is unchanged and retrained only when
   the data changes or you press **Train / retrain model**.

## Uploading your own data

Go to **Dataset and Settings** and upload a CSV with:

| Column | Required | Example |
|---|---|---|
| `timestamp` | yes | `2025-03-01 14:00` |
| `usage_kwh` | yes | `1.35` |
| `temperature_c` | no | `9.5` |

Readings must be **hourly** and there must be at least 72 rows (3 days); a few weeks or more gives much
better results. The app reports problems clearly: missing columns, unreadable dates (removed),
duplicate timestamps (first kept), missing or negative usage (removed), and missing temperatures
(interpolated, or ignored if mostly empty). Without temperature, the model simply runs without it.

## What the metrics mean

- **MAE** (mean absolute error): the average size of a mistake, in kWh. Lower is better.
- **RMSE** (root mean squared error): like MAE but punishes large mistakes more. Lower is better.
- **R²**: how much of the variation in usage the model explains. 1 is perfect, 0 is no better than
  predicting the average, negative is worse.
- **Baseline**: always predicting the training average. A useful model must beat it, and the app
  shows both side by side.

All scores come from the held-out test set, calculated when the model trains.

## Limitations

- Predictions are estimates; the model only knows patterns present in its training data.
- Future predictions need the previous 24 hourly readings, taken from the data or typed in by you.
  The temperature for a future hour is something you choose, not a forecast.
- The model can be less reliable for unusual conditions (heatwaves, holidays, new appliances,
  absences) that are rare or absent from the training data.
- Synthetic data is simpler than real life, so its scores are not representative of real homes.
- Only hourly data is supported, and one dataset is used at a time.
